# 질문·답변·상담을 보호하는 과정

[전체 기능](../README.md) · [AI 상담](../architecture/chat-flow.md) · [상담사 연결](counselor-handoff.md)

고객 질문과 생성 답변, 상담 메시지를 각 경로에 맞게 검사합니다. 관리자는 검사 기록과 정책 후보를 보고 정상 질문을 막는 오차단과 위험 표현을 놓치는 문제를 함께 검토합니다.

## 어디에서 검사하나요?

| 위치 | 확인하는 내용 | 화면에 이어지는 결과 |
|---|---|---|
| 질문 입력 | 금지어·프롬프트 공격·입력 형식, 필요한 경로의 AI 안전 판정 | 처리 시작 또는 차단·보류 안내 |
| 생성 답변 | 응답 구조, 제공한 근거, 조회 자료의 수치·상품 정보, 위험 표현 | 검사한 답변·부분 보류 또는 실패 안내 |
| 공식 FAQ 직접 반환 | 등록한 답변의 코드 검사 | 허용한 공식 답변. 생성과 출력 AI 판정은 생략 |
| 상담 메시지 | 공통 금지어와 금지 문장의 의미 유사도 | 허용한 메시지 전달, 차단·검사 실패 상태 표시 |

모든 질문이 같은 모델 검사를 거치지는 않습니다. 원문 검색으로 충분한 경우와 질문 정리가 필요한 경우를 구분합니다. 활성화한 검사가 실패하면 정상 통과로 간주하지 않습니다.

## 관리자가 정책을 개선합니다

1. 관리자가 검사 기록을 살펴보고 분석을 실행하거나 주기 분석을 설정합니다.
2. 서버는 분석한 자료에서 금지어 후보와 위험 문장 경고를 만듭니다.
3. 화면에서 후보를 수정하고 오차단·회귀 검사를 요청합니다.
4. 서버는 검사 당시 후보와 정책 버전, 검사 유효성을 확인합니다.
5. 관리자가 승인하면 기존 금지어 관리에 반영합니다.

후보를 수정하거나 검사가 만료되면 다시 검사해야 합니다. 일부 사례 페이지를 읽은 것만으로 전체 검사 통과를 판단하지 않으며, 최종 승인 조건은 서버가 다시 확인합니다. 위험 문장 경고의 읽음 처리와 금지어 승인은 별개입니다.

상담 금지 문장은 별도로 관리합니다. 등록·내용 수정 후 서버가 자동 색인을 진행하고 화면은 상태를 보여 줍니다. 심각도만 바꿀 때 기존 벡터를 끄지 않으며, 색인 실패 시 재시도를 제공합니다.

## 검사 결과를 해석할 때

검사는 위험을 줄이기 위한 장치이며 모든 새로운 표현의 미탐·오차단을 없애지는 않습니다. 정책 회귀 테스트와 실제 모델 평가를 구분하고, 기존 실험의 모델·질문·판정 조건을 함께 확인합니다.
