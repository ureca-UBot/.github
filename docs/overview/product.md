# 시나리오로 보는 UBot

[제품 소개](../../profile/README.md) · [전체 기능](../README.md)

UBot은 통신 상품·이용 정보·매장·고객 지원을 한곳에서 제공하고, AI와 상담사가 고객의 질문을 이어서 처리하도록 돕습니다. 고객의 이용 과정, 관리자의 개선 과정, 운영자의 서비스 관리 과정이 서로 연결됩니다.

## 1. 고객이 필요한 정보를 찾고 행동합니다

고객은 [상품 화면](../features/products-and-subscriptions.md)에서 요금제·홈상품·부가서비스·로밍·결합상품을 살펴봅니다. 로그인하면 본인 회선에 가입된 상품과 사용량·청구·약정을 확인하고 가입·변경·해지를 요청할 수 있습니다. 화면은 요청 결과를 서버에서 다시 확인해 표시합니다.

메뉴에서 찾기 어려운 내용은 [AI 채팅](../architecture/chat-flow.md)에 질문합니다. 서버는 공식 FAQ를 검색하고, 질문에 따라 상품·본인 이용 정보·매장 자료를 조회합니다. 화면은 답변과 관련 카드를 보여 주어 고객이 필요한 정보를 확인하고 다음 행동을 선택하게 합니다.

고객센터에서는 로그인 없이 카테고리별 FAQ와 공식 답변을 읽을 수 있습니다. 채팅의 상품 목록에서는 조건을 단계별로 골라 상품을 바로 다시 조회합니다. 신규 회선 가입 전에는 사용할 전화번호의 중복 여부도 확인합니다.

매장 방문이 필요하면 [매장 찾기](../features/stores-and-reservations.md)에서 주변 매장과 경로를 확인하고 방문 시간을 예약합니다. 예약 내역과 알림으로 진행 상태를 다시 확인할 수 있습니다. 처리할 문의가 남으면 [고객 지원](../features/customer-support.md)에 문의를 남깁니다.

사람의 도움이 필요할 때 로그인한 고객이 [상담사를 호출](../features/counselor-handoff.md)합니다. 상담사는 서버에 저장된 같은 대화의 AI 문답·FAQ 선택·허용된 이전 상담 기록을 확인합니다. 상담이 끝난 뒤에도 고객은 [기존 대화 목록](../features/accounts-and-conversations.md)에서 기록을 다시 볼 수 있습니다.

배정된 상담사는 앞선 문답과 함께 고객의 현재 회선·가입 상품을 조회합니다. 고객 정보 조회는 상담사 역할과 현재 참여 권한을 확인하며, 상담 종료 뒤에는 허용하지 않습니다.

## 2. 관리자가 반복되는 문의를 지식으로 바꿉니다

검색 근거가 부족한 질문은 고객에게 보류 결과를 안내하고 [미응답 개선 대상](../features/knowledge-improvement.md)으로 남깁니다. 관리자는 비슷한 질문을 묶어서 확인하고, 대표 질문·반복 건수·사유를 보고 FAQ를 새로 만들거나 보완합니다.

FAQ의 현재 질문 표현을 다시 임베딩해 검색에 반영합니다. 이전 미응답과 바뀐 FAQ의 검색 대응도 확인합니다. 이때 재검증은 검색 개선을 확인하는 과정이며, 최종 답변을 전부 다시 생성해 평가하는 과정은 아닙니다.

관리자는 인기·급상승 질문과 지역별 유사 문의 증가를 함께 살펴볼 수 있습니다. 문의 급증 알림을 확인한 뒤 실제 상황을 판단하고 공지나 FAQ 개선으로 대응합니다. 급증 감지가 통신망 장애를 확정하거나 공지를 자동 등록하지는 않습니다.

[안전 정책](../features/ai-safety.md)도 관리자가 검토합니다. 코드와 AI 판정이 질문·답변·상담 메시지를 검사하고, AI가 제안한 차단 후보는 검증과 승인 뒤 정책에 반영합니다. 상담 기록 전체를 자동으로 FAQ로 전환하지는 않습니다.

## 3. 운영자가 배포 이후의 결과를 확인합니다

변경한 코드는 CI 검증을 거쳐 배포합니다. 운영자는 서비스 상태와 작업 진행 상황을 확인하고, 이상 신호가 생기면 지표·로그·알림에서 원인을 좁혀 갑니다.

답변 처리 중 프로세스나 의존 서비스가 멈춰도 저장된 작업을 기준으로 복구합니다. 복구 뒤에는 프로세스가 다시 실행되는지뿐 아니라 기존 요청이 어떤 상태로 끝났는지 확인합니다. 상세 과정은 [배포·관측·장애 대응](../features/service-operations.md)에서 설명합니다.

AWS BE에서는 배포 셸 밖의 타이머가 멈춘 Worker를 다시 기동하고, 실행된 Worker가 저장 작업을 회수합니다. [ServerTest](https://github.com/ureca-UBot/UBot-ServerTest)에 부하·장애 실험과 실제 관리자 화면 검증 결과를 보관합니다.

비용은 요청 수와 모델 계산량을 함께 봅니다. 조건에 맞는 공식 FAQ를 직접 반환하면 생성 호출을 줄일 수 있고, 검색 때 만든 벡터를 후속 처리에서 재사용할 수 있습니다. API·답변 처리·모델 실행을 나눠 필요한 자원을 조절할 수 있습니다. 처리량·지연·오류를 함께 측정해 용량을 결정합니다.

## 사용자별로 확인하는 결과

| 사용자 | 확인하는 결과 |
|---|---|
| 고객 | 상품·이용 정보, 답변과 카드, 방문 예약, 문의 답변과 알림, 이전 대화 |
| 상담사 | 고객의 앞선 문답과 FAQ 선택, 현재 회선·가입 상품, 검사한 상담 메시지와 진행 상태 |
| 관리자 | FAQ·상품·매장·공지·문의 상태, 미응답 개선 대상, 문의 추이와 정책 검토 결과 |
| 운영자 | 배포 결과, 서비스·데이터·모델 상태, 장애 원인과 작업 복구 결과 |

## 구현 범위와 근거

가입·청구·사용량은 UBot 내부 데이터로 처리합니다. 실제 통신사의 개통·과금 원장이나 결제 승인을 연동한 제품은 아닙니다. 클라우드 구성은 실행 역할을 나눠 운영할 수 있게 하지만, 현재 가동 중인 자원이나 자동 확장 여부는 배포 환경에서 확인해야 합니다.
